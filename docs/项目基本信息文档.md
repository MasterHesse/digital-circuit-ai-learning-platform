
  - Bolt：`bolt://localhost:7687`
  - 用户名/密码：`neo4j / neo4j_pwd`

  - `jdbc:postgresql://localhost:5433/diglearn`

## 4. 数据模型（Data Model）

### 4.1 Neo4j 图模型（知识点）

**节点 Label：** `KnowledgePoint`

字段（对应 Java 实体 `KnowledgePoint`）：

- `kpId: String`（唯一 ID，`@Id`）
- `title: String`
- `category: String`
- `difficulty: Integer`

**关系类型：** `:PREREQ`

方向约定：

- `(A:KnowledgePoint)-[:PREREQ]->(B:KnowledgePoint)`
- 含义：A 的前置知识点是 B（A 依赖 B）

---

### 4.2 PostgreSQL（电路存档）

对应实体：`CircuitArchiveEntity`  
表名：`circuit_archives`

字段（按实体语义）：

- `id: UUID`（主键，`@GeneratedValue`）
- `name: varchar/text`（非空）
- `circuit_json: TEXT`（非空，存储电路 JSON 的字符串形式）
- `created_at: Instant`（`@CreationTimestamp`）
- `updated_at: Instant`（`@UpdateTimestamp`）

> 当前实现使用 `TEXT` 存 JSON；

## 5. 后端代码结构（当前已知模块）

包名根：`dev.masterhesse.diglearn`

### 5.1 knowledgepoint（Neo4j）

- `KnowledgePointController`：知识点 REST API
- `KnowledgePointRepository`：Neo4j Repository + 自定义 Cypher（前置链）
- `PrereqDto`：`/prereqs` 的输出 DTO（包含 depth）

### 5.2 circuit（Postgres/JPA + 模拟配置）

- `CircuitArchiveController`：电路存档 REST API
- `CircuitArchiveService`：存取逻辑（JSON 序列化/反序列化）
- `CircuitArchiveRepository`：JPA Repository
- `CircuitSaveRequest`：保存请求 DTO（`name` + `circuit: JsonNode`）
- `CircuitResponse`：响应 DTO（含 `id/createdAt/updatedAt`）
- `SimConfigController`：模拟器/编辑器的“策略配置”接口（允许的元件列表）

## 6. 对外 API 列表与用法
> 下述路径均以后端 `http://localhost:8080` 为基址。

### 6.1 知识点：获取详情

- Method：`GET`
- Path：`/api/kp/{kpId}`

```bash
curl -s http://localhost:8080/api/kp/DL-080
```

- 200：返回 `KnowledgePoint`
- 404：不存在

---

### 6.2 知识点：获取前置知识点（按深度展开）

- Method：`GET`
- Path：`/api/kp/{kpId}/prereqs`
- Query：
  - `depth`：`1..3`，默认 `2`

```bash
curl -s "http://localhost:8080/api/kp/DL-080/prereqs?depth=3"
```

- 200：`List<PrereqDto>`
- 404：起点不存在（Controller 会先 `existsById`）
- 400：depth 越界（`@Min/@Max` 校验触发）

---

### 6.3 电路存档：创建（保存电路 JSON）

- Method：`POST`
- Path：`/api/circuits`
- Body：`CircuitSaveRequest`

示例：

```bash
curl -s -X POST "http://localhost:8080/api/circuits" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "and-demo",
    "circuit": {
      "devices": {
        "A": {"type": "Button", "label": "A"},
        "B": {"type": "Button", "label": "B"},
        "G1": {"type": "And", "label": "AND1", "bits": 1, "inputs": 2},
        "Y": {"type": "Lamp", "label": "Y"}
      },
      "connectors": [
        {"from": {"id":"A","port":"out"}, "to": {"id":"G1","port":"in1"}},
        {"from": {"id":"B","port":"out"}, "to": {"id":"G1","port":"in2"}},
        {"from": {"id":"G1","port":"out"}, "to": {"id":"Y","port":"in"}}
      ],
      "subcircuits": {}
    }
  }'
```

成功响应：`CircuitResponse`

- 200：返回 `id/name/circuit/createdAt/updatedAt`
- 400：参数校验失败（`name` 为空、`circuit` 为 null 等）

---

### 6.4 电路存档：按 ID 读取

- Method：`GET`
- Path：`/api/circuits/{id}`（UUID）

```bash
curl -s "http://localhost:8080/api/circuits/<UUID>"
```

- 200：`CircuitResponse`
- 404：不存在（`circuit not found...`）
- 500：理论上仅当库里 `circuitJson` 不是合法 JSON（Service 会报 “stored circuitJson is invalid JSON”）

---

### 6.5 模拟配置：允许的组件列表

- Method：`GET`
- Path：`/api/sim/component-policy`

返回结构：

```json
{
  "allowedComponents": ["And", "Or", "Not"]
}
```

> 当前实现是写死的 `List.of("And","Or","Not")`，可作为前端“组件白名单”来源。

## 8. 命名规范

### 8.1 知识点 ID（kpId）

- `kpId`：知识点唯一 ID（Node 主键 / API 路径参数）
- `depth`：前置展开深度（查询参数/DTO 字段；从 1 开始）
- `category`：知识点分类/章节（字符串）
- `difficulty`：难度（整数，范围可后续定义）

示例:
```text
DC-FND-01
DC-BOOL-01
DC-SEQ-04
```

### 8.2 电路存档（Circuit Archive）

- `id`：UUID（后端生成）
- `name`：电路名（用户输入）
- `circuit`：DigitalJS 的 circuit JSON（原样存储）
